**Gap:** Web page has content-first project instructions but no reusable,
vendored writing inventory for projects centered on documents, stories or
worlds. The initial software/UI bases do not supply that authoring guidance.

**User-directed scope:** add optional writing capabilities accessible from Web
page's AGENTS routes, without making every webpage session read fiction-writing
material. Content remains free to use interactivity, illustration, audio, video
and animation. The template is content-led, not a prohibition on rich media.

Offer suitable authoring workflows as project-visible skills using the usual
harness discovery directories. Vendor their complete resource closure and
teach beginners that they can discover and invoke these skills. Keep reusable
reference guidance available without requiring every task to invoke a skill.
Verify actual project discovery as well as the copied file layout.

Candidate capability concerns:

- Reader/audience, purpose, voice, document structure, editing and revision.
- Plot types and story structures, scene purpose, pacing and narrative arcs.
- Worldbuilding with consistent rules, settings, timelines and constraints.
- Character documents: motivation, relationships, voice, development and
  continuity; compact reference sheets rather than mandatory bulky bibles.
- Cross-document continuity and a source-of-truth organization for prose,
  characters, world facts and supporting media.

Compose a relevant union of bases and vendor routed instructions, examples or
document starters so projects stand alone. Additional writing capabilities
should be discoverable for later requests using the same library standards.
Use triggers based on the user's actual authoring task, not forced application
of every plot scheme to every document. Keep general software/runtime guidance
separate from writing guidance. Do not turn optional capabilities into a
mandatory fiction stack for a portfolio or factual reference page.

**Closure evidence:** review the composed instructions from a plain information
page, a multipage reference and an interactive story. Trace a character change,
world-rule change and revision across documents; check that conflicting facts
have one owner and all referenced guidance is vendored. Evaluate readability
and useful authoring behavior, not merely instruction length. The broader
[portable-base gap](portable-capability-bases.md) still governs global filtering
and editorial quality; this entry owns the missing writing capabilities.

## Shared static-publication onboarding

Web page is intended for publication, for example to GitHub Pages. Most
serverless Canvas games/apps share that path, so publishing guidance belongs
in a reusable capability available to both templates, not a prose-only branch.

The default destination uses the host-provided URL without buying or configuring
a custom domain. Domain setup is an optional extension, not an onboarding gate.

Develop concise, effective, vendorable onboarding for:

- Starting from a user-supplied email and helping establish a GitHub account
  when needed, with user-owned identity, verification and authentication steps.
- Creating or selecting a repository, building the static bundle and publishing
  to GitHub Pages without inheriting the template author's personal destination.
- Choosing/registering a new domain or using an existing one, configuring the
  Pages/custom-domain and DNS relationship, and verifying HTTPS and real reach.
- Clear follow-up publishing commands, asset/base-path behavior, update checks
  and failure recovery. Keep credentials out of project content.

Use supported provider paths verified when the guidance is authored. Explain
exactly which identity verification, purchase and access-grant steps require
the user; prepare concrete configuration before requesting those actions.
Publication and domain/DNS changes require the user's chosen destination and
authorization, not merely permission to instantiate a template. A project
that activates the optional backend needs an appropriate server host for its
API; GitHub Pages serves only its static client.

Validate onboarding from both a new account/domain scenario and an existing
repository/domain, including a subpath-hosted Canvas app. The done condition
is a reachable intended site plus usable repeat-publication instructions,
not just a successful build or a guessed vendor UI path.
