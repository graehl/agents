# CHART: A Harness-Rotation Curriculum for   
Harness-Robust Search Agents

###### Abstract

Search agents are usually trained under a single harness. But once an agent is deployed in a real application, its harness is frequently updated (e.g., a rewritten system prompt) to fit production needs. This exposes a fragility of post-trained agents: because a learned behavior is entangled with its training harness, even a harness update that leaves the task unchanged can fail to elicit the behavior. In this study, we train a search agent to perform parallel search, a popular strategy for improving both the efficiency and the performance of search. We find that training under a fixed harness makes the behavior _harness-local_ , overfit to that harness’s surface form: when the harness changes, the model falls back to serial search. An intuitive idea is _harness augmentation_ , but simply creating more harnesses for training does not completely resolve the problem. GRPO learns from the reward gap between parallel and serial rollouts of the same question: a small harness pool saturates that gap early, while a large pool dilutes the per-harness signal too thinly for any harness to consolidate. We therefore propose Curriculum HArness Rotation Training (CHART), a rotating curriculum that lets a search agent gradually consolidate parallel search across harnesses. At each periodic evaluation, CHART “graduates” the harnesses on which the expected behavior has been learned and replaces them with harnesses that are still learnable, which keeps the reward gap alive throughout training. Starting from the same harness pool, CHART makes the model learn parallel search on all harnesses, whereas static augmentation succeeds on at most half of them. The behavior also carries to held-out harnesses: CHART parallelizes on \(89\%\) of held-out turns, against at most \(5\%\) for the static pools. It further transfers to a new QA task and search environment, improving pass@1 by \(5.6\)pp over the best static pool. Besides, we show that CHART-trained agents benefit more from meta-harness search than other baselines.

## 1 Introduction

Language-model agents increasingly act by calling external tools—searching the web, querying APIs, running code—inside a multi-turn loop. Reinforcement learning (RL) with verifiable rewards is now the standard way to teach these agents useful behaviors [[7](https://arxiv.org/html/2609.22247#bib.bib7), [25](https://arxiv.org/html/2609.22247#bib.bib25)], one of the most valuable being _intra-turn parallelism_ : issuing several search queries at once rather than one at a time, which cuts latency and, on many questions, improves coverage [[9](https://arxiv.org/html/2609.22247#bib.bib9)].11 1 Appendix [B](https://arxiv.org/html/2609.22247#A2 "Appendix B Budget-Matched Parallel vs. Sequential Search ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents") verifies both in our setting with a budget-matched sequential baseline. But an agent is never deployed as bare weights. It runs behind a _harness_ —a system prompt that frames the task, names the tools, and implicitly or explicitly suggests a search strategy—and this harness is rewritten constantly downstream: a product team adds a persona, translates it, imposes a format, or strips it to one line. Behaviors acquired through RL should be _robust_ to these rewrites. We show they are not.

#### Learned behavior is harness-local.

Under a fixed training harness, RL installs parallel search as a habit tied to that harness’s surface form: a model that parallelizes on \(91\%\) of turns under its own training harness holds only \(45\%\) on harnesses that still ask for parallel search, and just \(2\%\) on those that do not (§[5.1](https://arxiv.org/html/2609.22247#S5.SS1 "5.1 Fixed Pools vs. Rotation ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")). The capability is intact—the model issues parallel searches only when the wording matches training, the agentic analogue of the prompt sensitivity of frozen LLMs [[23](https://arxiv.org/html/2609.22247#bib.bib23), [15](https://arxiv.org/html/2609.22247#bib.bib15), [35](https://arxiv.org/html/2609.22247#bib.bib35)]. A routine deployment-time rewrite thus silently deletes a behavior the model provably possesses.

#### Static harness augmentation does not fix it.

The obvious response is _harness augmentation_ —train over many harness variants so that no single phrasing is load-bearing, the instinct behind multi-template instruction tuning [[28](https://arxiv.org/html/2609.22247#bib.bib28), [22](https://arxiv.org/html/2609.22247#bib.bib22), [27](https://arxiv.org/html/2609.22247#bib.bib27)] and, now, frontier agent training [[10](https://arxiv.org/html/2609.22247#bib.bib10)]. Yet _static_ mixing fails at every pool size: for both small and large training pools, parallel search becomes the default on only a minority of harness styles (§[5.1](https://arxiv.org/html/2609.22247#S5.SS1 "5.1 Fixed Pools vs. Rotation ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents"))—more variants buy _cue-following_ , not _internalization_. The failure is in the RL dynamics, not the pool size: GRPO [[24](https://arxiv.org/html/2609.22247#bib.bib24)] learns from a _within-group contrast_ —the reward gap between parallel and serial rollouts of the same question—which a small pool exhausts (its harnesses saturate and the contrast vanishes) while a large pool dilutes, splitting each step’s rollout budget so thinly across harnesses that none consolidates. Static augmentation is trapped between the two.

#### Curriculum harness augmentation.

The fix is to _schedule_ the harnesses rather than mix them, so the within-group contrast never runs out. CHART, Curriculum HArness Rotation Training, keeps a small active window of harnesses; the moment one saturates, CHART “graduates” it and swaps in a fresh, still-learnable one, so every batch keeps a live parallel-vs-serial contrast and the behavior spreads across structurally diverse styles. This is a curriculum over the _harness_ , not the problem: prior curriculum RL orders _problems_ by difficulty [[4](https://arxiv.org/html/2609.22247#bib.bib4), [29](https://arxiv.org/html/2609.22247#bib.bib29), [6](https://arxiv.org/html/2609.22247#bib.bib6), [20](https://arxiv.org/html/2609.22247#bib.bib20)], whereas we order which harness styles are active over training. Critically, rotation draws from the _same_ pool as static augmentation; only its organization in time changes.

#### Findings.

From the identical pool, CHART makes parallel search the default on \(100\%\) of harnesses (up from at most \(48\%\) under static augmentation), generalizing to cue-free and _never-trained_ held-out styles and beating every static pool by \(5.6\)pp pass@1 on a new QA task and search environment, at no accuracy cost. The through-line is that _sequencing matters more than diversity_. Robustness also pays off downstream: a CHART-trained model has a _flatter harness-loss landscape_ , making meta-harness search [[31](https://arxiv.org/html/2609.22247#bib.bib31), [34](https://arxiv.org/html/2609.22247#bib.bib34), [1](https://arxiv.org/html/2609.22247#bib.bib1)] converge to better harnesses, \(+12.6\)pp over an untrained substrate.

#### Contributions.

  * A new failure mode for agentic RL. RL under a fixed harness makes a learned behavior _harness-local_ —the model keeps the capability but deploys it only under training-style prompts—and _static_ harness augmentation fails at _every_ pool size, exhausting the within-group contrast RL learns from (§[3](https://arxiv.org/html/2609.22247#S3 "3 Problem and Method ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents"), §[5.1](https://arxiv.org/html/2609.22247#S5.SS1 "5.1 Fixed Pools vs. Rotation ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")). 
  * Curriculum harness augmentation. We introduce, to our knowledge, the first curriculum over the _harness interface_ rather than problem difficulty (CHART): from the _same_ pool it turns harness-local behavior into a default robust across unseen styles, never-trained held-out harnesses, and an out-of-distribution (OOD) task and environment, at no accuracy cost (§[3](https://arxiv.org/html/2609.22247#S3 "3 Problem and Method ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents"), §[5.2](https://arxiv.org/html/2609.22247#S5.SS2 "5.2 Robustness and OOD Transfer ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents"), §[5.4](https://arxiv.org/html/2609.22247#S5.SS4 "5.4 Ablations ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")). 
  * Robustness as a better substrate. Harness-robustness reshapes the model’s harness-loss landscape, making a CHART-trained model a strictly better substrate for automatic meta-harness search (\(+12.6\)pp, §[5.3](https://arxiv.org/html/2609.22247#S5.SS3 "5.3 Meta-Harness Search ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")). 



## 2 Related Work

#### Harness robustness.

Frozen LLMs are notoriously sensitive to superficial prompt changes—formatting, ordering, paraphrasing, and adversarial perturbation all shift accuracy, and a single prompt overstates ability [[23](https://arxiv.org/html/2609.22247#bib.bib23), [15](https://arxiv.org/html/2609.22247#bib.bib15), [32](https://arxiv.org/html/2609.22247#bib.bib32), [21](https://arxiv.org/html/2609.22247#bib.bib21), [35](https://arxiv.org/html/2609.22247#bib.bib35), [17](https://arxiv.org/html/2609.22247#bib.bib17)]. These works _measure_ prompt sensitivity; we _remove_ it during RL, and unlike inference-time hardening the robustness _generalizes to unseen harness styles_. Our failure mode is its agentic analogue: the same task, reworded, flips the agent between parallel and serial search.

#### RL for search and tool-using agents.

RL with verifiable rewards teaches LLMs to search and use tools—Search-R1 [[7](https://arxiv.org/html/2609.22247#bib.bib7)], R1-Searcher [[25](https://arxiv.org/html/2609.22247#bib.bib25)], ZeroSearch [[26](https://arxiv.org/html/2609.22247#bib.bib26)], ToRL [[13](https://arxiv.org/html/2609.22247#bib.bib13)], and long-horizon search agents [[8](https://arxiv.org/html/2609.22247#bib.bib8)]—but targets _acquiring_ competence under a single fixed prompt. We study an orthogonal axis, the robustness of a learned behavior to the harness, and show fixed-prompt training produces harness-local behavior that fails to generalize. Concurrent frontier work varies the harness during RL—Kimi K3 trains over composable harness configurations to avoid overfitting to any single tool schema or system prompt [[10](https://arxiv.org/html/2609.22247#bib.bib10)]—but mixes them statically; we ask whether the learned behavior stays harness-local and show that _scheduling_ , not mixing, internalizes it.

#### Curriculum RL for LLMs.

Curriculum learning [[4](https://arxiv.org/html/2609.22247#bib.bib4)] for LLM RL orders _problems_ by difficulty [[29](https://arxiv.org/html/2609.22247#bib.bib29), [6](https://arxiv.org/html/2609.22247#bib.bib6), [20](https://arxiv.org/html/2609.22247#bib.bib20)] or synthesizes problems targeting model weaknesses [[14](https://arxiv.org/html/2609.22247#bib.bib14)]; distributionally robust objectives push for uniform performance across groups [[18](https://arxiv.org/html/2609.22247#bib.bib18)]. Our rotation is instead a curriculum over the _harness_ , aiming at behavioral generalization across harnesses rather than accuracy on hard problems. The weakness-driven selection of [Liang et al. [14]](https://arxiv.org/html/2609.22247#bib.bib14) resembles our swapping in low-parallel harnesses, but acts on synthesized problems, not the harness interface.

#### Automatic prompt and harness optimization.

A large line of work searches for a better prompt with the model fixed—OPRO, APE, evolutionary search, and agentic optimizers [[31](https://arxiv.org/html/2609.22247#bib.bib31), [34](https://arxiv.org/html/2609.22247#bib.bib34), [5](https://arxiv.org/html/2609.22247#bib.bib5), [33](https://arxiv.org/html/2609.22247#bib.bib33), [3](https://arxiv.org/html/2609.22247#bib.bib3), [1](https://arxiv.org/html/2609.22247#bib.bib1)]—and, closest to us, Meta-Harness [[12](https://arxiv.org/html/2609.22247#bib.bib12)] optimizes the harness end-to-end. Our meta-harness search (§[5.3](https://arxiv.org/html/2609.22247#S5.SS3 "5.3 Meta-Harness Search ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")) is in this lineage but serves as a _probe_ : CHART changes the _weights_ to be robust across harnesses, and we ask whether that makes harness search easier.

## 3 Problem and Method

### 3.1 Notation

We train a search agent with group-relative policy optimization (GRPO) [[24](https://arxiv.org/html/2609.22247#bib.bib24)]. The agent answers each question in at most \(T\) turns, each issuing up to \(P\) searches at once before reading their results: a \(T{\times}P\) search budget in which \(T\) is _depth_ (serial multi-hop search) and \(P\) is _width_ (parallel search). A turn is _parallel_ if it issues \(>1\) call. A _harness_ \(h\) is a system prompt framing the task; the same question can appear under many harnesses that differ in surface form while leaving the task unchanged (§[4](https://arxiv.org/html/2609.22247#S4 "4 Experimental Setup ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")). Its _parallel rate_ \(\mathrm{PR}\%\) is the fraction of turns that are parallel, over eval rollouts under \(h\), and \(h\) is _covered_ when \(\mathrm{PR}\%\geq 0.80\). We report both mean \(\mathrm{PR}\%\) and _coverage_ , the number of covered harnesses: mean \(\mathrm{PR}\%\) can be lifted by partial parallelism spread everywhere, whereas coverage counts where parallel search is reliably the default.

#### Reward.

The reward is purely outcome-based: \(r=r_{\mathrm{correct}}+0.1\,r_{\mathrm{format}}\), an LLM-judge verdict \(r_{\mathrm{correct}}\in\{0,1\}\) on the final answer plus a format check. _No term rewards parallelism_ , so any parallel-vs-serial preference arises entirely from the within-group correctness contrast (§[5.1](https://arxiv.org/html/2609.22247#S5.SS1 "5.1 Fixed Pools vs. Rotation ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")).

### 3.2 CHART: Curriculum HArness Rotation Training

CHART trains the same pool as a _curriculum over the harness_ rather than a static mixture. GRPO learns from a _within-group contrast_ —the reward gap between parallel and serial rollouts of the same question—which any fixed pool eventually exhausts (§[5.1](https://arxiv.org/html/2609.22247#S5.SS1 "5.1 Fixed Pools vs. Rotation ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")). CHART instead keeps only a small _rotating window_ of active harnesses, _graduating_ each as it saturates and _replacing_ it with a fresh, still-learnable one; because saturated harnesses are continually swapped out, the window always retains a live contrast, and parallel search spreads across the whole pool.

#### The rotating window.

From a pool \(\mathcal{H}\) (\(|\mathcal{H}|{=}33\)) we keep \(N\) _active_ harnesses \(A_{t}\subseteq\mathcal{H}\) at eval step \(t\). Write \(\mathrm{PR}\%_{t}(h)\in[0,1]\) for the parallel rate of harness \(h\) on the step-\(t\) eval and \(\mathcal{G}_{t}\) for the graduated set. Training runs as usual on \(A_{t}\); the two rules below say who leaves and who arrives.

#### Graduation trigger.

Every 20 steps we run a lightweight in-pool eval (50 datapoints per harness) to estimate \(\mathrm{PR}\%_{t}(h)\) for each active harness, and graduate every active harness that eval shows as covered:22 2 We graduate at \(0.85\) rather than at the \(0.80\) coverage bar itself—a margin that absorbs the noise of a 50-datapoint estimate (Appendix [C](https://arxiv.org/html/2609.22247#A3 "Appendix C Eval Sample-Size Validation ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")) and keeps arrival strictly below departure.



\[\begin{aligned}
 & \mathcal{G}_{t}=\mathcal{G}_{t-1}\cup\{\,h\in A_{t-1}:\mathrm{PR}\%_{t}(h)\geq 0.85\,\}. &  & \text{(1)}
\end{aligned}\]

 

Because graduation is checked only at these periodic evals, a harness keeps training past the bar until the next eval, which we find matters for consolidation (§[5.4](https://arxiv.org/html/2609.22247#S5.SS4 "5.4 Ablations ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")).

#### Replacement selection.

We refill the freed slots from the learnable, not-yet-graduated candidates \(\mathcal{H}\setminus(\mathcal{G}_{t}\cup A_{t-1})\), choosing those whose parallel rate is closest to the center \(c{=}0.60\) of a band \([0.40,0.80]\) whose upper end is the coverage bar itself, so the incoming harness is learnable but not yet covered—closer to graduation and it has little left to teach:



\[\begin{aligned}
 & A_{t}=\bigl(A_{t-1}\setminus\mathcal{G}_{t}\bigr)\;\cup\;\operatorname*{arg\,min}_{\,S}\;\sum_{h\in S}\bigl|\mathrm{PR}\%_{t}(h)-c\bigr|,\quad S\subseteq\mathcal{H}\setminus(\mathcal{G}_{t}\cup A_{t-1}),\;|S|=N-|A_{t-1}\setminus\mathcal{G}_{t}|. &  & \text{(2)}
\end{aligned}\]

 

When \(N{>}1\) the swap is _staggered_ —only graduated harnesses are replaced, so the surviving “anchors” stabilize the batch across the switch. If no candidate lies in the band we take the highest-\(\mathrm{PR}\%\) one, and once the pool is exhausted the survivors keep training to convergence.

## 4 Experimental Setup

#### Data and model training.

We train Qwen3-30B-A3B-Thinking-2507 [[30](https://arxiv.org/html/2609.22247#bib.bib30)] with GRPO (global batch 512, \(16\) samples \(\times\) \(32\) groups) on \(32\) H100 GPUs. Our data is MiroVerse-v0.1 [[16](https://arxiv.org/html/2609.22247#bib.bib16)], keeping only questions answerable with web search. A difficulty filter runs the base model \(16\) times per question, scores each with an LLM judge, and uses the _effective pass rate_ (EPR, fraction correct) to split questions into _easy_ (\(\mathrm{EPR}>0.60\)), _learnable_ (\(0<\mathrm{EPR}\leq 0.60\)), and _hard_ (\(\mathrm{EPR}=0\)). We train on the learnable band (\(16{,}712\) questions) and sample \(50\) per band for the \(150\)-question val set used in §[5.1](https://arxiv.org/html/2609.22247#S5.SS1 "5.1 Fixed Pools vs. Rotation ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents"), §[5.2](https://arxiv.org/html/2609.22247#S5.SS2 "5.2 Robustness and OOD Transfer ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents"), and §[5.4](https://arxiv.org/html/2609.22247#S5.SS4 "5.4 Ablations ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents"). Each run trains for 200 steps at 512 rollouts/step with \(T{=}5\) turns and \(P{=}5\) calls per turn, a \(25\)-search cap per question.

#### Harness pool.

We author 33 harnesses with Claude Code [[2](https://arxiv.org/html/2609.22247#bib.bib2)] spanning wide surface diversity—wording, persona, language, verbosity, and agent format—grouped by _how much the harness tells the model what to do_ (Appendix [A](https://arxiv.org/html/2609.22247#A1 "Appendix A Harness Pool Design ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")): A–Explicit (10 harnesses) state the parallel strategy outright; B–Implicit (9) only hint at it; C–Framework (9) recast the task in agent formats (ReAct, plan-and-execute, function/XML calls); and D–Minimal (5) give near-zero cues, testing whether parallel search is internalized. A/C are _cue_ harnesses that request or frame parallel search; B/D are _cue-free_ , never mentioning it—the split between “parallelizes only when asked” and “parallel-as-default” used throughout. Each run samples one harness per GRPO group; the methods we compare differ in which they draw (§[5.1](https://arxiv.org/html/2609.22247#S5.SS1 "5.1 Fixed Pools vs. Rotation ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")).

Finally, the shopping agent task (\(19\times 200\)) swaps the data itself, a separate product-search set (its validation split; §[5.3](https://arxiv.org/html/2609.22247#S5.SS3 "5.3 Meta-Harness Search ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents") uses the test split) and search environment, testing transfer to a new QA distribution. The 12 held-out and 19 shopping harnesses were authored with Claude Code [[2](https://arxiv.org/html/2609.22247#bib.bib2)] like the training pool, but no evaluated style overlaps a trained one. ### 5.1 Fixed Pools vs. Rotation

#### Pool size does not buy parallelism.

We first show the contrast-exhaustion of §[3](https://arxiv.org/html/2609.22247#S3 "3 Problem and Method ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents") is not a corner case of one badly-sized pool but the outcome of _every_ fixed pool. The five fixed models of Table [2](https://arxiv.org/html/2609.22247#S5.T2 "Table 2 ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents") differ only in pool size, all seeded from the same _learnable_ mid-band harnesses at \(\sim\)40–80% base parallel rate (§[3](https://arxiv.org/html/2609.22247#S3 "3 Problem and Method ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")). The cue-vs-cue-free gap is the diagnostic: a model that has _internalized_ parallel search scores high on _both_ , while one that merely follows instructions scores high on cue and low on cue-free. No fixed pool lifts cue-free parallelism past \(13\%\) (5% at base) or covers more than \(16\) of the 33 harnesses, at any pool size—against \(91\%\) and \(29/33\) for a rotating window. The two ends fail for opposite reasons (§[3.2](https://arxiv.org/html/2609.22247#S3.SS2 "3.2 CHART: Curriculum HArness Rotation Training ‣ 3 Problem and Method ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")): fixed-1 consolidates on the one harness it trains (its \(\mathrm{PR}\%\) \(63\%\to 91\%\)) and spreads to little else (cue 45%, cue-free 2%, \(6/33\)), while fixed-33 spreads so thin that no harness consolidates, ending _below_ base on both mean \(\mathrm{PR}\%\) (18% vs. 24%) and cue \(\mathrm{PR}\%\) (32% vs. 37%). Pool size has an interior optimum: fixed-3 through fixed-9 outscore both ends on pass@1 (0.484–0.507, against 0.456 for fixed-1 and 0.425 for fixed-33)—yet every fixed pool stays cue-only (cue 45–89% against cue-free 2–13%).

#### Rotation improves on fixed pools at the right width.

Moving the window is worth \(+32\)pp cue-free \(\mathrm{PR}\%\) and \(16\) more covered harnesses at \(N{=}1\), \(+57\)pp and \(14\) more at \(N{=}3\), and \(+84\)pp and \(21\) more at \(N{=}5\). Width sets a ceiling, though, since each step’s 512 rollouts split \(N\) ways—\(\sim\)170 per harness at \(N{=}3\) but only \(\sim\)57 at \(N{=}9\), too few to consolidate before graduation: just \(4\) harnesses graduate in the whole run and CHART-9 ends _below_ fixed-9 (\(7\%\) vs. \(13\%\) cue-free, \(7/33\) vs. \(16/33\)). Counterintuitively, more parallelism does not keep paying either: CHART-5 reaches \(91\%\) cue-free \(\mathrm{PR}\%\), \(26\)pp above \(N{=}3\), and still only ties it on in-pool pass@1 (\(0.512\)). We take \(N{=}3\)—the narrower window at equal accuracy—as the operating point for the rest of the paper, and read these results as one hypothesis: _what internalizes parallel search is a pool that keeps turning over—enough for the behavior to spread—rather than one that is merely large._

### 5.2 Robustness and OOD Transfer

#### Setup.

We now ask whether the behavior is _robust, transferable, and free of accuracy cost_ : does it carry to cue-free held-out harnesses, and to a different QA distribution answered through a different search environment (the held-out and shopping columns of Table [2](https://arxiv.org/html/2609.22247#S5.T2 "Table 2 ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents"))?

#### Robustness across harnesses.

Training on a fixed pool does not transfer at all: every fixed pool sits at 0–5% held-out \(\mathrm{PR}\%\) against the untrained base’s 2%, even though every held-out harness states the per-turn call budget outright—the behavior is tied to the trained wording, not to the opportunity. Every rotating window from \(N{=}1\) to \(N{=}5\) instead reaches 71–99%, and CHART-3 and CHART-5 take the top two spots on held-out pass@1 (\(0.513\) and \(0.506\)); since CHART-3 also ties for the best in-pool figure, the same window tops both evaluations, with no width trade-off between accuracy and robustness. The benefit of parallelism does saturate, though: held-out pass@1 climbs steeply with \(\mathrm{PR}\%\) at first (\(0.392\) at CHART-1’s 71%, \(0.513\) at CHART-3’s 89%), but the last 10pp up to CHART-5’s 99% buys nothing (\(0.506\))—the same plateau §[5.1](https://arxiv.org/html/2609.22247#S5.SS1 "5.1 Fixed Pools vs. Rotation ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents") found in-pool.

#### OOD transfer (shopping).

The shopping task changes the questions, the search environment, and the harnesses at once, so nothing here was seen in training. Fixed pools transfer none of the behavior to it: they parallelize on 6–23% of turns against the untrained base’s 5%, and their pass@1 (\(0.361\)–\(0.381\)) straddles the base’s \(0.375\), with three of the five landing below it—at this distance, training on a fixed pool is worth nothing. Every rotating window up to \(N{=}5\) instead parallelizes on 52–81% of turns and scores \(0.426\)–\(0.437\), beating the best fixed pool by \(5.6\)pp. Since neither the task, the environment, nor the harnesses were trained on, the gap cannot be attributed to overfitting.

We give CHART-3 60 steps past the shared budget (200\(\to\)260) to see where the remaining gains land. They land where parallelism still had room to grow (Table [3](https://arxiv.org/html/2609.22247#S5.T3 "Table 3 ‣ OOD transfer \(shopping\). ‣ 5.2 Robustness and OOD Transfer ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")): in-pool and held-out were already at 85–89% \(\mathrm{PR}\%\) and move little, whereas shopping, still only 59% parallel, rises to 100% and gains \(5.4\)pp pass@1—the largest gain of the three, on the one task the model never trained on. ### 5.3 Meta-Harness Search

#### Setup.

We ask whether a more-trained substrate lets the _same_ meta-harness search [[12](https://arxiv.org/html/2609.22247#bib.bib12)] find a better harness. For each of three frozen checkpoints—the untrained base, CHART-1, and CHART-3—we run an identical search that tunes only the system prompt, never the weights: from a hand-written seed pool we keep the top 5 by _validation_ pass@1, then each round every seed proposes 5 mutations (\(5\times 5{=}25\) candidates), we re-rank the _entire cumulative history_ , and the top 5 reseed the next round. We score the final top 5 _once_ on a held-out _test_ set and report _best-of-search_ , the validation champion’s test score, and _top-5 mean_ , their mean. We search two tasks: the shopping agent task, using the two splits of the shopping product-search set (§[4](https://arxiv.org/html/2609.22247#S4 "4 Experimental Setup ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")), and deep-research QA, with the miroverse validation set of §[4](https://arxiv.org/html/2609.22247#S4 "4 Experimental Setup ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents") and a test set of FRAMES [[11](https://arxiv.org/html/2609.22247#bib.bib11)] and seal_hard [[19](https://arxiv.org/html/2609.22247#bib.bib19)].44 4 200 questions randomly sampled from FRAMES (compute limits) plus 254 from seal_hard.

#### Rotation length.

The first knob, with \(N{=}3\) fixed, is how long we rotate: is rotation only a _warm-up_ , switchable off once the model has a general disposition to parallelize? Two runs share their first 100 steps, then fork—early-stop freezes the pool and keeps training on it, full-run keeps rotating. It is not: passive generalization stalls at the cue boundary. Early-stop does keep generalizing on its own, but only to cued styles: it covers 14 harnesses against full-run’s 23, and just \(1\) of them is cue-free against \(4\). The parallel rates of Table [7](https://arxiv.org/html/2609.22247#S5.T7 "Table 7 ‣ 5.4 Ablations ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents") put the same boundary in plain view: the two are close wherever the prompt asks for parallel search and far apart everywhere it does not. Rotating longer is not costly either: full-run also ends with the higher mean pass@1. Rotation must therefore run throughout, not only early.

#### Refill rule.

The second knob is _which_ harness fills a freed slot: we replace CHART’s learnable-band draw (\(\mathrm{PR}\%\in[0.40,0.80]\), §[3](https://arxiv.org/html/2609.22247#S3 "3 Problem and Method ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")) with a uniform draw over the not-yet-graduated harnesses (Table [7](https://arxiv.org/html/2609.22247#S5.T7 "Table 7 ‣ 5.4 Ablations ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")). Random refill is the weakest arm in the study, losing to CHART-3 and even to fixed-3—to not rotating at all—by \(12\)pp of pass@1 averaged over the three tasks. Its draws land on near-zero-\(\mathrm{PR}\%\) harnesses—nothing to consolidate—and by step \(180\) no seed harness is left. The cost is accuracy, not parallel usage: \(\mathrm{PR}\%\) holds at a fixed pool’s level while pass@1 drops below it—rotation is only as good as what it rotates _in_.

#### Graduation trigger.

The third knob is _when_ a harness leaves once its parallel rate reaches the graduation bar. Eval-only checks only every \(\sim\)20 steps, so a passing harness overshoots to \(\mathrm{PR}\%\approx 0.95\)–\(1.0\) before leaving; EMA+eval also tracks a per-step exponential moving average (EMA) of each harness’s parallel rate over its _training_ rollouts and graduates the instant that estimate crosses the bar. Table [9](https://arxiv.org/html/2609.22247#S5.T9 "Table 9 ‣ Graduation trigger. ‣ 5.4 Ablations ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents") shows faster graduation loses on every metric: both reach high cue \(\mathrm{PR}\%\) (100% vs. 82%), but on cue-free eval-only holds 65% while EMA collapses to 13%, and held-out pass@1 follows at 0.513 vs. 0.372. EMA also graduates _fewer_ harnesses despite leaving each sooner—4 vs. 12, stalling by step 60 (Table [9](https://arxiv.org/html/2609.22247#S5.T9 "Table 9 ‣ Graduation trigger. ‣ 5.4 Ablations ‣ 5 Results ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")); its active harnesses stay stuck at \(0.54\)–\(0.63\), never nearing the bar. That overshoot is where the behavior _consolidates_ into a default: EMA skips it, so parallel never generalizes and the pool stops turning over.

## 6 Discussion and Limitations

We showed that RL-learned agent behavior can be harness-local—an agent trained to search in parallel reverts to serial search when the harness is reworded—and that this is a training-dynamics failure: loss of within-group contrast after saturation. CHART, a curriculum over the harness, keeps that contrast alive and spreads harness-robust parallel behavior to unseen styles, new QA distributions, and new search environments at no accuracy cost, which in turn flattens the harness landscape and makes downstream meta-harness search more effective.

#### Limitations.

We study one behavior—intra-turn parallel search—on one base model, Qwen3-30B-A3B, so generalization to other agent behaviors and model families is open. We also vary only the harness’s system prompt, leaving tool-interface changes such as renamed or distractor tools to future work.

## Appendix A Harness Pool Design

The 33-harness pool was authored with Claude Code and organized into four groups by how much the harness tells the model what to do (§[4](https://arxiv.org/html/2609.22247#S4 "4 Experimental Setup ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")). Group A (Explicit, 10) states the parallel strategy outright and serves as the training anchor—the model already parallelizes here, so it gives stable positive signal; variants cover wording, persona (“fact checker,” “academic researcher”), verbosity, output formatting, and language (including Chinese-language variants that state the per-turn parallel budget in Chinese, e.g. “5 parallel calls per turn”). Group B (Implicit, 9) hints at the behavior without naming it (“maximize information per round,” “multiple sources,” “batch your queries,” time pressure, and a Chinese implicit variant). Group C (Framework, 9) recasts the same task in popular agent formats—thought/action/observation (ReAct-style), plan-and-execute, an explicit agent loop, hypothesis-driven investigation, decompose-and-search, iterative refinement, a terse machine-readable system spec, a conversational framing, and a bare toolbox listing—to test format-invariance. Group D (Minimal, 5) strips behavioral cues to near zero (a two-line minimal prompt, a tools-only listing, a one-sentence instruction, the task buried in unrelated boilerplate, and a long tool list with no strategy guidance), testing whether parallel search has been internalized rather than instructed. One further adversarial prompt was authored—it actively steers toward serial, one-query-at-a-time search—but is excluded from the pool and from every eval reported here, so the pool is \(33=10+9+9+5\).

## Appendix B Budget-Matched Parallel vs. Sequential Search

We test the paper’s premise—that parallel search improves both accuracy and efficiency (§[1](https://arxiv.org/html/2609.22247#S1 "1 Introduction ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents"))—with a budget-matched pair of single-harness runs. Both train from the same base model (Qwen3-30B-A3B) on the same data with the same additive reward under one fixed harness, and differ _only_ in how the \(\sim\)25-search budget is spent: the _sequential_ baseline issues one call per turn (up to \(T{=}25\) turns, pure serial depth), while the _parallel_ harness—the fixed-1 harness used elsewhere in the paper—issues several calls per turn. The reward adds no parallel or efficiency bonus, so any gap reflects the search strategy alone. Both are evaluated on the same 150-prompt val set (\(pass@1\), \(N{=}1\)).

---|---|---|---|---|---|---  
Sequential (\(P{=}1\), \(T{=}25\)) | 0.473 | 10.9 | 11.9 | 10.9 | 67.0k | 2.1k  
Parallel (fixed-1, \(P{=}5\), \(T{=}5\)) | 0.513 | 2.5 | 3.4 | 10.5 | 26.5k | 2.2k

 

Table [10](https://arxiv.org/html/2609.22247#A2.T10 "Table 10 ‣ Appendix B Budget-Matched Parallel vs. Sequential Search ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents") shows parallel search is Pareto-better. It is more _accurate_ (\(+4.0\)pp \(pass@1\); the gain concentrates on the learnable slice, \(+11.4\)pp, with easy saturated and hard tied within \(N{=}1\) noise) and more _efficient_ : issuing \(\sim\)4 calls per turn, it reaches the same budget in \(4.4\times\) fewer turns and \(3.5\times\) fewer LLM calls. The efficiency is structural rather than shorter generations—both runs issue about the same number of searches (\(10.5\) vs. \(10.9\)) and produce about the same output length (\(2.2\)k vs. \(2.1\)k tokens); the saving is that the sequential agent re-encodes its growing context every turn and so processes \(2.5\times\) more input tokens (\(67\)k vs. \(26\)k). Here _input tokens_ counts the prompt (prefill) tokens the model reads summed over all its LLM calls in a trajectory—since the full conversation so far (system prompt, question, and every prior turn’s reasoning and tool results) is re-sent on each call, this grows with the number of turns—and _output tokens_ counts the tokens the model generates, summed over the same calls; both are then averaged over the 150 prompts. Input tokens thus measures how much context the model must re-encode end-to-end, while output tokens measures raw generation.

## Appendix C Eval Sample-Size Validation

The graduation trigger (§[3](https://arxiv.org/html/2609.22247#S3 "3 Problem and Method ‣ CHART: A Harness-Rotation Curriculum forHarness-Robust Search Agents")) reads a lightweight in-pool eval of 50 datapoints per harness, so its \(\mathrm{PR}\%\) estimate carries roughly \(\pm 8\)pp of binomial noise. We validate that this is nonetheless enough to make the same graduation decision as the \(3\times\) larger eval used for reporting. On two checkpoints of the rotation run (iter_59 and iter_79) we ran the full standalone eval—33 harnesses \(\times\) 150 questions, \(N{=}1\), temperature 1.0—and asked, for each harness, whether the two evals make the same graduate / keep-training call at the graduation threshold.

They agree on 32/33 harnesses (97%) at both checkpoints. The single disagreement is the same harness each time, and it is one whose parallel rate genuinely oscillates across steps rather than one the eval mis-measures (50-datapoint eval reads \(90\%\), standalone reads \(78\%\)). The consequence of such a false graduation is mild: the harness leaves the active window slightly early and is replaced by a mid-band harness that still provides contrast signal. We therefore use 50-datapoint eval for graduation and checkpoint selection, and 150-question eval for all reported numbers.

## Appendix D Meta-Harness Search Breakdown

#### The lever differs by task.

In both settings, training equips the model to exploit a harness the base model cannot, but through different mechanisms. On deep-research, the base model searches serially by default—its champion harness operates at \(6\%\) \(\mathrm{PR}\%\), and forcing parallel execution on the base model _reduces_ accuracy—so the behavior must be trained before search can exploit it; the benefit of training is thus the emergence of parallelism (the selected harness’s \(\mathrm{PR}\%\) increases \(6\%\to 90\%\to 100\%\) along base\(\to\)CHART-1\(\to\)CHART-3, accounting for the \(+12.6\)pp improvement). On shopping, parallelism is already saturated on every checkpoint (\(100\%\) \(\mathrm{PR}\%\) even at base, as the winning harness prescribes fully parallel search), yet pass@1 still increases by \(10.0\)pp with \(\mathrm{PR}\%\) fixed at \(100\%\); here training instead enables deeper verification, as the top-5 harnesses issue more tool calls (mean \(8.7\to 13.1\to 13.4\), predominantly product_info attribute checks, at a stable rate of \(\sim\)4.7 calls per turn). In both cases the trained substrate lets search select a stronger harness—one that parallelizes (deep-research) or verifies more thoroughly (shopping) in a manner unavailable to the base model.
